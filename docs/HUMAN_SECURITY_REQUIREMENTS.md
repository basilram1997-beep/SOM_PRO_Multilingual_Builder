# Human Security Requirements

## Purpose

This document records the minimum people-and-process controls required for privileged access in SOM PRO deployments.

## Requirements

- Staff with access to school data must be vetted according to applicable law and organization policy.
- Privileged users must sign confidentiality and acceptable-use terms.
- Security and privacy training should be completed at least annually.
- Shared administrator accounts should not be used.
- Every privileged account must be named and tied to a responsible person.
- Support and incident access must be temporary, approved, and logged.
- Review of privileged access must be recorded and repeated on a yearly cycle or before major release changes.

## Privileged access rules

- Use named accounts for all operators.
- Keep access limited to what the role needs.
- Review access changes and deny unnecessary permissions.
- Log privileged access and sensitive support actions.

## Support and incident handling

- Support access must be approved, scoped, and time-limited.
- Support users should not browse school data without a reason.
- Incident review ownership must be documented.
- Sensitive HR/security actions should be visible to the vendor security owner or delegated compliance reviewer.
- Human-security controls should be part of the release checklist, not an informal promise.
