## Tenant Isolation Assessment

Result: PARTIAL

`schoolId` is generally derived server-side from authenticated token context in `apps/backend/src/middleware/auth.ts:72-81` and exposed through `getRequestSchoolId` in `apps/backend/src/services/schoolContext.ts:32-44`. The app-level middleware rejects client-supplied `schoolId` and `userId` in write bodies in `apps/backend/src/middleware/requestProtections.ts:353-390`. The Prisma schema has broad school ownership and compound indexes/uniques across core models in `apps/backend/prisma/schema.prisma:379-1146`.

An expanded runtime test now exists in `apps/backend/src/services/tenantIsolation.security.test.ts`. It seeds two schools and proves that a school A admin cannot access or mutate school B data through selected student list/context, attendance read/write, class update, teacher and teacher-assignment update, subject update, base schedule writes/swaps, daily schedule/event access, archive delete, report queries, operations metadata for report exports and backup jobs, upload storage context, audit-log detail/list, school dashboard, school export, or school delete-data endpoints.

The remaining gap is full route inventory coverage. The suite still needs to prove the same negative behavior for every grade/certificate/import/notification/export/download path, backup file access path, report artifact path, and every remaining route/resource ID. This should remain a high-priority Ministry pilot blocker until covered.

## Executive Gap Summary

### P0 - Critical / Block Ministry Pilot

- Tenant-isolation testing now has an expanded runtime baseline across core operational routes, but it is not yet comprehensive across every route, grade/certificate/import/notification/export/download path, backup file path, and resource ID.
- MFA backend enforcement now exists for privileged users, but frontend rollout, reset ceremony, and production policy evidence are not complete.
- Ministry supplier standards from `sapakim.education.gov.il` were not officially verified, so the matrix cannot claim formal compliance.
- License server is a security boundary but still uses local JSON storage and recovery can expose an admin password.
- Production HTTPS is only a placeholder in nginx deployment, and real staging HTTPS evidence is missing.

### P1 - Required Before Production

- Complete real SSO/OIDC/SAML or approved Ministry identity integration once provider details are verified.
- Complete staging deployment on a real domain with TLS, monitoring, backup/restore drill, and outage tests.
- Improve audit log evidence: actor/userId/source/result, immutable export, case-insensitive redaction, no delete/update route tests.
- Add real SAST/DAST, SBOM, license scanning, dependency review, and fail-closed audit in CI.
- Harden Electron with explicit sandbox, URL allowlists, code signing, and update integrity.
- Encrypt backups, add checksum/signature, retention enforcement, and documented RPO/RTO.
