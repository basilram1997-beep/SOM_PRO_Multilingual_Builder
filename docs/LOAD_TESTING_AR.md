# اختبار الحمل

هذا الاختبار يقيس سلوك النظام عند عدد مستخدمين متوقعين مع الحفاظ على نفس مسار التطبيق الحقيقي.

## الهدف

- معرفة كيف يستجيب backend تحت حمل أقرب للاستخدام اليومي.
- مراقبة وقت الاستجابة.
- مراقبة الأخطاء، خصوصًا `5xx` و `429`.
- التأكد أن الحفظ في الحضور والدرجات والتقارير يبقى مستقرًا.

## الأمر

```bash
npm run load:test
```

## ماذا يشغّل

- تشغيل كامل عبر `scripts/stress-run.js`
- preset افتراضي أعلى من الضغط الخفيف
- حفظ النتائج داخل `tests/load/artifacts`
- إنشاء تقرير JSON وMarkdown لكل تشغيل

## الإعدادات الافتراضية

- `STRESS_SCENARIO=all`
- `STRESS_LOGIN_USERS=30`
- `STRESS_LOGIN_CONCURRENCY=10`
- `STRESS_REQUESTS=40`
- `STRESS_CONCURRENCY=10`

## متى نعده ناجحًا؟

- لا توجد أخطاء شبكة أو 5xx.
- login يبقى مستقرًا.
- حفظ الحضور والدرجات لا ينتج تكرارًا أو فقدًا للبيانات.
- التقارير تبقى قابلة للتوليد تحت الضغط.

## تعديل الحمل مؤقتًا

يمكنك تخفيف أو زيادة الحمل عبر environment variables:

```bash
STRESS_LOGIN_USERS=20 STRESS_CONCURRENCY=8 npm run load:test
```

## ملاحظة

إذا أردت مقارنة “load” مقابل “stress” بشكل أوضح، استخدم `load:test` للحمل المتوقع و`stress:test` للحالات القصوى أو الانقطاع المقصود.
