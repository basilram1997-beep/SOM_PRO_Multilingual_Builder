# Desktop Data Storage Audit

هذا المستند يلخص نتيجة فحص التخزين المحلي في SOM PRO.

## الخلاصة

- لا توجد قاعدة بيانات محلية في Desktop تحفظ بيانات الطلاب أو العلامات أو الحضور.
- البيانات التشغيلية الحقيقية يجب أن تبقى في Backend / PostgreSQL.
- Desktop wrapper في وضع `saas` يجب أن يفتح الويب الآمن فقط، ولا يشغّل قاعدة بيانات محلية ولا Backend محليًا.
- التخزين المحلي المسموح به يجب أن يبقى غير حساس ومحدودًا جدًا.

## ما وجدناه محليًا

- `apps/desktop/src/desktopDevice.js`
  - ينشئ `device.json` في مجلد التطبيق المحلي.
  - المحتوى الحالي هو معرّف تثبيت ومعلومات إنشاء فقط.
  - لا يحتوي على بيانات طلاب أو علامات أو حضور.

- `apps/frontend/src/i18n/i18n.tsx`
  - يحفظ اللغة المختارة في `localStorage`.
  - هذه قيمة تفضيل واجهة غير حساسة.

- `apps/frontend/src/features/auth/useLogin.ts`
  - حالة "تذكرني" تستخدم ذاكرة تشغيل فقط.
  - لا تُخزن كلمة المرور أو التوكن في التخزين الدائم.

- `apps/frontend/src/features/students/gradeEntryDraft.ts`
  - المسودات محفوظة في الذاكرة فقط أثناء الجلسة.
  - لا تُكتب إلى ملف محلي أو قاعدة بيانات محلية.

- `apps/frontend/src/i18n/translationSafety.ts`
  - يحتفظ بنسخة احتياطية محلية من مفاتيح الترجمة.
  - هذا التخزين غير حساس، لأنه لا يحتوي على بيانات تشغيل مدرسية.

## ما يجب ألا يُخزن محليًا

- بيانات الطلاب.
- الصفوف وربطها التشغيلي.
- العلامات.
- الحضور والغياب.
- الملاحظات الأكاديمية والسلوكية.
- التقارير التشغيلية.
- مفاتيح الترخيص أو أسرار المالك.
- كلمات المرور أو التوكنات الدائمة.

## قاعدة العمل

أي ميزة جديدة يجب أن تسأل أولًا:

1. هل يمكن حفظها في Backend بدل المتصفح؟
2. هل هذه البيانات حساسة؟
3. هل يمكن حذفها من Desktop دون كسر التشغيل؟

إذا كانت الإجابة نعم، فالقاعدة هي:

- الحفظ في Backend.
- منع التخزين المحلي الدائم.
- إبقاء Desktop مجرد wrapper أو طبقة تشغيل خفيفة.
