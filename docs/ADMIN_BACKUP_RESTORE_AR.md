# النسخ الاحتياطي والاسترجاع للمدير

هذا الملف يحدد الحد الأدنى المطلوب قبل تشغيل النظام في مدرسة حقيقية.

## قاعدة عامة

لا تحدث البرنامج أو تنقل الجهاز قبل أخذ نسخة احتياطية من قاعدة البيانات وملفات الترخيص.

## قبل التحديث

1. أوقف استخدام البرنامج من المستخدمين.
2. تأكد أن لا توجد عملية إدخال بيانات نشطة.
3. شغل:

   ```bash
   npm run update:backup
   ```

4. خذ نسخة من ملفات خادم الترخيص إن كانت مخزنة محلياً.
5. احفظ النسخة في مكانين مختلفين على الأقل.

للتحديث المنظم الكامل استخدم:

```bash
npm run update:safe
```

هذا الأمر يأخذ backup، يطبق migrations، يفحص الصحة، ويحاول rollback تلقائياً إذا فشل التحديث.

## ما يجب نسخه

- قاعدة بيانات PostgreSQL الخاصة بـ SOM PRO.
- بيانات خادم الترخيص المحلي عند استخدامه.
- ملفات البيئة المحلية `.env` الموجودة على جهاز التشغيل.
- أي ملفات مرفوعة من المستخدمين إذا كان التخزين المحلي مفعلاً.

## فحص النسخة الاحتياطية

- حجم النسخة ليس صفراً.
- تاريخ النسخة هو تاريخ يوم التحديث.
- يمكن قراءة ملف النسخة من وسيط تخزين آخر.
- تم تسجيل اسم المدرسة والإصدار ووقت النسخ.

## الاسترجاع

1. أوقف خدمات SOM PRO.
2. أعد قاعدة البيانات من النسخة الاحتياطية.
3. أعد ملفات الترخيص والبيئة إذا لزم.
4. شغل PostgreSQL وRedis.
5. شغل البرنامج.
6. تحقق من الدخول وفتح الطلاب والتقارير.

## حالات يجب فيها عدم المتابعة

- فشل استرجاع قاعدة البيانات.
- اختلاف إصدار قاعدة البيانات عن إصدار البرنامج بدون ترحيلات.
- ضياع ملف الترخيص المحلي.
- وجود خادم قديم على `4000` أو `4100`.
