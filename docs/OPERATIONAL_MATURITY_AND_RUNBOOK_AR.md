# الطبقة التشغيلية والنضج الميداني لـ SOM PRO

هذه الوثيقة تجمع ما يحتاجه المشروع ليبدو ناضجًا تشغيليًا، لا مجرد منظم داخليًا.

## 1) المراقبة والتنبيهات

### ما هو موجود

- يوجد Health-related docs.
- توجد تقارير أمنية وإدارية.
- توجد AuditLog لبعض الأحداث الحساسة.

### ما الذي ما زال مطلوبًا

- تنبيهات عند فشل تسجيل الدخول المتكرر.
- تنبيه عند تعطل الترخيص أو انتهاء الـ grace period.
- تنبيه عند فشل backup أو restore.
- تنبيه عند توقف الخادم المحلي أو remote service.

### المطلوب قبل البيع

- جدول يوضح: ما الذي يراقب، من يستقبل التنبيه، ومتى يعتبر الأمر حرجًا.

## 2) النسخ الاحتياطي والاستعادة

### ما هو موجود

- توجد وثائق اختبار backup/restore.
- توجد سكربتات backup وrestore في `deploy/scripts/`.

### ما الذي يجب تثبيته عمليًا

- جدولة نسخة احتياطية يومية.
- فحص نجاح النسخة الاحتياطية.
- تجربة restore دورية على بيئة منفصلة.
- توثيق زمن الاستعادة المتوقع.

### قواعد مهمة

- لا تكتفِ بالنسخ فقط؛ الاستعادة هي الاختبار الحقيقي.
- لا تخلط backup الاختباري مع بيانات الإنتاج.

## 3) تدهور الخدمة عند انقطاع الشبكة

### السلوك المطلوب

- إذا انقطع الاتصال مؤقتًا: يظهر وضع Grace واضح إذا كان الترخيص يسمح.
- إذا انتهت مهلة grace: يظهر منع واضح ورسالة مفهومة.
- لا تُفقد بيانات الطالب أو المدرسة بسبب الانقطاع.
- لا تُنفذ عمليات خطرة بدون تحقق.

### ما الذي يجب توثيقه

- ماذا يحدث في أول 5 دقائق.
- ماذا يحدث بعد ساعة.
- ماذا يحدث بعد انتهاء grace period.
- ماذا يرى المدير بدل الرسائل التقنية.

## 4) توثيق العميل غير المبرمج

### المطلوب

- صفحة واحدة واضحة: كيف أشغّل، كيف أوقف، كيف أصلح، ومتى أتصل بالدعم.
- لغة أبسط من لغة المطور.
- أمثلة قصيرة بدل الشرح المطول.

### المستهدف

- مدير مدرسة.
- موظف دعم.
- مستلم جديد للمشروع.

## 5) browser flows و E2E

### ما يجب تغطيته

- تسجيل الدخول.
- تبديل اللغة.
- القوائم الجانبية.
- إدخال العلامات.
- الشهادات.
- البرنامج اليومي.
- الترخيص.
- وضع offline / reconnect.

### الخلاصة العملية

الـ E2E الحالي جيد كأساس، لكنه ما زال يحتاج تغطية متصفح فعلية أوسع قبل أن يُعتبر إغلاقًا نهائيًا.

## 6) P0 / P1 / P2

| البند                      | المستوى | لماذا                           |
| -------------------------- | ------- | ------------------------------- |
| Clean Windows install      | P0      | يحدد قابلية التسليم الفعلية     |
| Signed installer           | P0      | مهم جدًا للثقة والتوزيع التجاري |
| Real staging with HTTPS    | P0      | يثبت أن SaaS يعمل خارج local    |
| Backup/restore rehearsal   | P1      | يحمي من فقدان البيانات          |
| Monitoring and alerts      | P1      | يحمي التشغيل بعد البيع          |
| Browser flows matrix       | P1      | يقلل مخاطر الواجهة والمتصفح     |
| Network degradation policy | P1      | يمنع توقف العمل بشكل مربك       |
| Smaller client docs        | P2      | يسهّل التسليم والدعم            |
| Extra CI polish            | P2      | يحسن الثقة ويقلل regressions    |

## الخلاصة

الطبقة التشغيلية أصبحت قوية، لكن لا تزال تحتاج إغلاقًا ميدانيًا من ثلاث زوايا:

1. التحقق الفعلي على staging وWindows نظيف.
2. النسخ الاحتياطي/الاستعادة والمراقبة.
3. توثيق أبسط للعميل غير المبرمج.
