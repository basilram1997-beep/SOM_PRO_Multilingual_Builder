# الاعتماديات والتراخيص في SOM PRO

هذا المستند يلخص مراجعة الاعتماديات الحالية من زاوية السلامة التجارية وقابلية البيع، بدون تغيير في سلوك المشروع.

## الخلاصة السريعة

- الاعتماديات المباشرة الحالية تبدو عادية ومناسبة لمشروع إنتاجي:
  - React
  - React DOM
  - Vite
  - TypeScript
  - Express
  - Prisma
  - Electron
  - electron-builder
  - Zod
  - Lucide React
  - Redis client
- لا توجد مكتبة كبيرة غير مبررة تمت إضافتها فقط لأجل هذه المراجعة.
- فحص الاعتماديات الأمني المحلي أعاد:
  - `0 vulnerabilities`
- لا توجد أسرار تراخيص أو مفاتيح ترخيص داخل هذا التقرير.

## ما هو آمن تجاريًا الآن

هذه الحزم مألوفة جدًا في منتجات تجارية حقيقية، ولا يظهر منها خطر ترخيص واضح في السياق الحالي:

| الحزمة                                    | الحالة التجارية                                  |
| ----------------------------------------- | ------------------------------------------------ |
| React / React DOM                         | آمنة ومعتادة                                     |
| Vite                                      | آمنة ومعتادة                                     |
| TypeScript                                | آمنة ومعتادة                                     |
| Express                                   | آمنة ومعتادة                                     |
| Prisma / @prisma/client                   | آمنة ومعتادة                                     |
| Electron / electron-builder               | آمنة ومعتادة لكن تحتاج اختبار تثبيت Windows فعلي |
| Zod                                       | آمنة ومعتادة                                     |
| Lucide React                              | آمنة ومعتادة                                     |
| dotenv / cors / helmet / morgan / ioredis | آمنة ومعتادة                                     |

## ما يحتاج مراجعة قبل البيع النهائي

حتى لو كانت الحزم آمنة، فإن بعض التحديثات الكبيرة ليست مجرد “ترقية عادية”:

| الحزمة          | ملاحظة                                                       |
| --------------- | ------------------------------------------------------------ |
| React 19        | متاح، لكن الترقية تحتاج اختبارًا على الواجهة كلها            |
| Prisma 7        | متاح، لكن الترقية تحتاج مراجعة migrations وclient generation |
| Electron 43     | متاح، لكن يجب اختبار Desktop وinstaller مرة أخرى             |
| Express 5       | متاح، لكن قد يغيّر سلوك بعض المسارات أو middleware           |
| Vite 8.1.x أحدث | يمكن تحديثه لاحقًا إذا لم يكسر build                         |

## ملاحظات عملية

- لا يوجد حاليًا دليل على أن أي اعتماد مباشر غير مناسب للبيع.
- التحديثات الكبيرة تبقى “تحسينًا مخططًا” وليست مطلبًا عاجلًا.
- إذا قررنا ترقية major versions، يجب أن يتم ذلك على دفعات مع:
  - build
  - lint
  - test
  - desktop checks
  - staging install

## التخزين المحلي

- التخزين المحلي في التطبيق يستخدم فقط لأمور غير حساسة مثل:
  - اللغة
  - حفظ دخول المستخدم بشكل اختياري
  - مسودات إدخال الدرجات
- رمز المالك لم يعد يُخزن في المتصفح.
- أي قيمة قديمة أو تالفة يتم إسقاطها بدل إبقائها.

## التوصية النهائية

- **آمن تجاريًا كبداية:** نعم.
- **مثالي قبل v1.0؟** ليس بعد، لأن بعض التحديثات الكبيرة ما زالت متاحة وتحتاج قرارًا مستقلًا.
- **هل يحتاج تغييرًا فوريًا في الاعتماديات؟** لا.
- **هل يحتاج مراجعة دورية؟** نعم، خصوصًا قبل أي بيع أو نشر staging جديد.
