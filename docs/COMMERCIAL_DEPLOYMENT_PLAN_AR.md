# خطة النشر التجاري لـ SOM PRO

## القرار الهندسي المعتمد

المسار التجاري الأفضل لـ SOM PRO هو SaaS مركزي:

- الخادم الخلفي Backend يعمل على سيرفر مركزي تملكه أنت.
- قاعدة البيانات PostgreSQL تعمل على السيرفر المركزي.
- خادم الترخيص License Server يعمل على السيرفر المركزي.
- تطبيق سطح المكتب يبقى واجهة Desktop لنفس واجهة الويب، ويتصل بالسيرفر عبر API.
- مدير المدرسة يثبت SOM PRO Setup.exe فقط.
- مدير المدرسة لا يحتاج Docker أو Node.js أو PostgreSQL محلي.

نسخة التشغيل المحلي تبقى للتطوير والتجربة فقط، وليست المسار التجاري الرئيسي.

## أوضاع التشغيل

### development

للمطور أثناء العمل اليومي.

- Frontend: غالبًا `http://localhost:5173`.
- Backend: غالبًا `http://localhost:4000`.
- License Server: غالبًا `http://localhost:4100`.
- يحتاج Node.js و Docker في بيئة التطوير.

### local-trial

لتجربة محلية على جهاز واحد.

- قد يحتاج Node.js و Docker.
- مناسب للفحص الداخلي أو عرض سريع.
- لا يُنصح به كنسخة تجارية للمدارس.

### saas

المسار التجاري.

- Desktop لا يحاول تشغيل backend محلي.
- Desktop لا يفحص Docker.
- Desktop يتصل مباشرة برابط API مركزي.
- الترخيص والتفعيل يتمان عبر السيرفر.

## ماذا يحتاج مدير المدرسة؟

في مسار SaaS:

- ملف SOM PRO Setup.exe فقط.
- اتصال إنترنت.
- كود ترخيص صادر من لوحة المالك.
- بريد وكلمة مرور مدير المدرسة.

لا يحتاج:

- Docker.
- Node.js.
- PostgreSQL.
- معرفة برمجية.

## ماذا يحتاج صاحب النظام؟

- سيرفر فعلي أو VPS.
- دومين حقيقي.
- HTTPS.
- PostgreSQL على السيرفر.
- تشغيل Backend و License Server كخدمات production.
- نسخ احتياطي لقاعدة البيانات.
- مراقبة logs والأخطاء.
- توقيع Windows installer قبل البيع.

## كيف يتم التفعيل؟

1. صاحب النظام ينشئ مدرسة من لوحة المالك.
2. يصدر ترخيصًا مرتبطًا باسم المدرسة ورقم المؤسسة.
3. يرسل للمدرسة كود الترخيص وبيانات الدخول الأولية.
4. تطبيق Desktop SaaS يتصل بالسيرفر المركزي.
5. السيرفر يقرر هل الترخيص فعال، منتهي، قراءة فقط، أو ملغى.

## كيف نحد من توزيع البرنامج بدون ترخيص؟

- التفعيل يتم عبر License Server مركزي.
- كل كود ترخيص مرتبط بمدرسة وعدد أجهزة.
- يمكن إلغاء الترخيص أو تحويله إلى قراءة فقط من لوحة المالك.
- نسخة SaaS لا تحمل قاعدة البيانات محليًا، لذلك نسخ البرنامج وحده لا يعطي بيانات أو صلاحية تشغيل كاملة.

## أين تحفظ البيانات؟

في مسار SaaS تحفظ البيانات في قاعدة PostgreSQL على السيرفر المركزي. هذا يجعل النسخ الاحتياطي، الإيقاف، التمديد، والصلاحيات تحت سيطرة صاحب النظام.

## كيف يتم التحديث مستقبلًا؟

- تحديث Backend يتم على السيرفر المركزي.
- تحديث Frontend Web يتم على السيرفر أو ضمن نسخة Desktop جديدة.
- تحديث Desktop installer يتم عند الحاجة فقط.
- لاحقًا يمكن إضافة auto-update، لكنه ليس ضمن هذه المرحلة.

## ما بقي قبل البيع التجاري؟

- تجهيز سيرفر production حقيقي.
- ربط دومين و HTTPS.
- إعداد أسرار production آمنة.
- تشغيل migration/seed production بشكل مضبوط.
- توقيع ملف Windows installer.
- اختبار SOM PRO Setup.exe على جهاز Windows نظيف.
- سياسة نسخ احتياطي واستعادة.
- مراقبة الأخطاء والتراخيص.
