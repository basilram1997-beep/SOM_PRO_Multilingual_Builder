# استراتيجية Browser E2E

هذه الوثيقة تشرح مسار اختبارات المتصفح الفعلية في SOM PRO.

## الحالة الحالية

- المسار المعتمد الآن هو Playwright.
- يمكن تشغيله عبر `npm run test:e2e:browser`.
- يمكن تشغيله بوضع مرئي عبر `npm run test:e2e:browser:headed`.
- يمكن تثبيت المتصفح عبر `npm run test:e2e:browser:install`.

## التقسيم الحالي

| الأولوية | التدفق               | الهدف                                          |
| -------- | -------------------- | ---------------------------------------------- |
| P0       | تسجيل الدخول والتنقل | التأكد أن الجلسة والواجهة يفتحان بشكل صحيح     |
| P0       | التنقل الأساسي       | الرئيسية، المعلمين، البرنامج اليومي، الإعدادات |
| P1       | الحضور والغياب       | تسجيل الحالة وحفظها وتصديرها                   |
| P1       | إدخال العلامات       | اختيار الصف والمادة والحفظ وربط الشهادات       |
| P1       | الشهادات             | المعاينة والتصدير والطباعة                     |
| P1       | الأرشيف              | حفظ اليوم وعرضه والتصدير                       |
| P2       | لوحة العمليات        | عرض التصديرات والنسخ الاحتياطية وسجل التدقيق   |

## قواعد التشغيل

- لا نعتمد على بيانات عشوائية.
- يجب تجهيز بيانات اختبار ثابتة قبل التشغيل.
- يجب أن يكون backend وlicense server جاهزين قبل بدء الاختبار.
- أي mojibake أو نص عربي/عبري مشوّش يجب إصلاحه في نفس السلسلة، لا تأجيله.

## ما لا نريده

- تكرار unit tests داخل Playwright.
- اختبار كل زر بلا قيمة.
- UI fragile يعتمد على نصوص مؤقتة أو بيانات غير ثابتة.

## التوسعة التالية

إذا أردنا توسيع المسار لاحقًا، فالأولوية تكون:

1. الشهادات.
2. إدخال العلامات.
3. الحضور والغياب.
4. الأرشيف.
5. لوحة العمليات.

## الخلاصة

Playwright هو المسار الفعلي المعتمد الآن لاختبارات المتصفح، ويجب أن يُشغَّل على بيئة مناسبة مع متصفح حقيقي وخدمات محلية أو staging جاهزة.
