# Backup and Restore Runbook

هذا الدليل العملي يوضح كيف نختبر النسخ الاحتياطي والاستعادة بدل أن تبقى مجرد فقرة نظرية.

## ما الذي يجب نسخه احتياطيًا

- PostgreSQL database.
- license storage إذا كان منفصلًا عن PostgreSQL.
- أي ملفات مرفقة تُضاف لاحقًا.
- أي بيانات أرشيفية دائمة.

## النسخ الاحتياطي

### PostgreSQL

```bash
deploy/scripts/backup-postgres.sh
```

النتيجة المتوقعة:

- ملف `.sql` داخل `deploy/backup/postgres/`.
- اسم الملف يحتوي timestamp واضحًا.

### License storage

إذا كانت بيانات الترخيص تُخزن في ملفات JSON أو مجلد منفصل، فأنشئ نسخة منه في نفس النافذة الزمنية الخاصة بالنسخ الاحتياطي.

## الاستعادة

### PostgreSQL

```bash
CONFIRM_RESTORE=yes deploy/scripts/restore-postgres.sh path/to/backup.sql
```

### بعد الاستعادة

- أعد تشغيل الخدمات.
- افتح `/health`.
- افتح `/api/version`.
- سجّل دخولًا تجريبيًا.
- تأكد أن المدرسة والطلاب والجداول عادت كما كانت.

## ما الذي نعتبره نجاحًا

- البيانات تعود كما كانت.
- التراخيص لا تتلف.
- البرنامج اليومي والشهادات والعمل اليومي يبقيان متماسكين.
- لا يحدث leak بين المدارس بعد الاستعادة.

## ما الذي نعتبره فشلًا

- فقدان بيانات المدرسة.
- تلف التراخيص.
- عودة بيانات مدرسة إلى مدرسة أخرى.
- توقف النظام بعد restore.

## ملاحظات مهمة

- لا تنفذ restore على Production بدون backup جديد مؤكد.
- لا تحفظ هذا الدليل وحده كبديل عن تجربة فعلية.
