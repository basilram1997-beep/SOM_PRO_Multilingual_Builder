# خطة اختبار الضغط لـ SOM PRO

هذا المستند يصف اختبارًا محدودًا وآمنًا لقياس سلوك التطبيق تحت ضغط خفيف قبل أي تجربة على staging أو production.

## النطاق

- الاختبار يكون على البيئة المحلية أو على staging فقط.
- لا تستخدم بيانات فعلية أو بيانات مدرسية حقيقية.
- لا تُشغّل الاختبار على production.

## ما الذي نراقبه

- زمن الاستجابة.
- عدد الطلبات الفاشلة.
- أخطاء الخادم.
- استقرار تسجيل الدخول.
- استقرار ترخيص البرنامج.
- استجابة الواجهة عند بطء الشبكة.

## نقاط الفحص المقترحة

1. `/health`
2. `/api/version`
3. `/api/auth/login`
4. `/api/license/status`
5. أحد endpoints القراءة الأساسية مثل `/api/teachers`

## أداة مناسبة

- يمكن استخدام `autocannon` أو أداة مشابهة خفيفة.
- ابدأ بعدد صغير من الطلبات، ثم زد تدريجيًا.

## مثال تشغيل

```bash
npx autocannon -c 5 -d 20 http://localhost:4000/health
```

## حدود آمنة

- ابدأ بـ 5 اتصالات فقط.
- لا تختبر عمليات حساسة بكثافة عالية.
- أوقف الاختبار إذا ظهرت أخطاء متكررة أو تسريب في الذاكرة.

## ماذا ندوّن

- متوسط زمن الاستجابة.
- أعلى زمن استجابة.
- عدد الأخطاء.
- هل بقيت الواجهة قابلة للاستخدام.
- هل استمر تسجيل الدخول والترخيص بالعمل.

## متى نعتبر الاختبار جيدًا؟

- إذا بقيت الخدمة مستقرة.
- ولم تظهر حالات انهيار.
- ولم يتدهور الأداء بشكل حاد.
- ولم تتعطل عمليات الدخول أو الترخيص.
