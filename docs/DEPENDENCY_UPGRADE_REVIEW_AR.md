# مراجعة ترقية الاعتماديات في SOM PRO

هذه المراجعة مبنية على `package.json` ونتيجة `npm outdated --long`، وهدفها توضيح ما يمكن تحديثه الآن بأمان نسبي، وما يجب تأجيله إلى دفعة اختبار مستقلة.

## الخلاصة التنفيذية

- **يمكن تحديثه الآن غالبًا بأمان:** أدوات البناء والتنسيق وبعض حزم التطوير الصغيرة.
- **يجب تأجيله لدفعة اختبار:** أي ترقية major أو أي حزمة تؤثر مباشرة في React / Prisma / Electron / Express / Zod.
- **السبب:** المشروع مستقر حاليًا والفحص الكامل يمر بنجاح، وأي ترقية كبيرة قد تفتح مشاكل غير مرتبطة بجودة الكود.

## ما يمكن تحديثه الآن بأمان نسبي

| الحزمة              |     من | إلى متاح | السبب                                                      |
| ------------------- | -----: | -------: | ---------------------------------------------------------- |
| `eslint`            | 10.6.0 |   10.7.0 | ترقية patch لأداة lint فقط                                 |
| `prettier`          |  3.9.3 |    3.9.5 | ترقية patch للتنسيق فقط                                    |
| `typescript-eslint` | 8.62.0 |   8.63.0 | patch tooling، تأثيره محدود                                |
| `vite`              |  8.1.0 |    8.1.4 | patch build tool، مع build check بعد التحديث               |
| `tsx`               | 4.22.4 |   4.23.1 | patch dev/test runner، مناسب للتحديث المرحلي               |
| `helmet`            |  8.2.0 |    8.3.0 | patch أمني بسيط، مع مراجعة سريعة بعد التحديث               |
| `app-builder-bin`   |  4.0.0 |    4.2.0 | ممكن لاحقًا، لكن يفضل اختباره مع Desktop build قبل اعتماده |

## ما يجب تأجيله

| الحزمة                      | الوضع الحالي | لماذا نؤجلها                                                   |
| --------------------------- | ------------ | -------------------------------------------------------------- |
| `react` / `react-dom`       | 18.x         | الترقية إلى 19.x قد تغيّر سلوك الواجهة وتتطلب اختبار شامل      |
| `prisma` / `@prisma/client` | 5.x          | major upgrade وقد يؤثر على migrations وclient generation       |
| `electron`                  | 42.x         | قد يؤثر مباشرة على Desktop وinstaller                          |
| `express`                   | 4.x          | major change وقد يؤثر في middleware والمسارات                  |
| `zod`                       | 3.x          | major upgrade يحتاج مراجعة لكل schemas                         |
| `lucide-react`              | 0.x          | القفزة إلى 1.x تستحق مراجعة UI كاملة                           |
| `@types/*` major jumps      | متعددة       | التحديث الكبير قد يسبب تحذيرات TypeScript لا علاقة لها بالمنطق |

## توصية عملية

### دفعة 1: تحديثات آمنة

نفّذ تحديثات الأدوات فقط ثم أعد:

- `npm run check`
- `npm run desktop:check`

بعدها راقب:

- lint
- build
- unit tests
- desktop packaging

### دفعة 2: التحديثات الكبيرة

نفّذها فقط بعد نافذة اختبار مستقلة:

- React 19
- Prisma 7
- Electron 43
- Express 5
- Zod 4

## ملاحظة تجارية

- لا يوجد سبب ملحّ يمنع البيع أو الـ staging بسبب الاعتماديات الحالية.
- لكن من الأفضل ألا نخلط بين:
  - **تحسين الأداة**
  - **تغيير جيل المكتبات**

## القرار المقترح

- **Update now:** أدوات التطوير والتنسيق والـ patch fixes.
- **Defer:** أي major upgrade.
