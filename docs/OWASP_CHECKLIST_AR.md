# قائمة مراجعة OWASP

## 1. Broken Access Control

- التحكم في الصلاحيات موجود في الباك إند.
- يجب مراجعة كل endpoint جديد قبل الإطلاق.
- يجب أن تبقى فلاتر `schoolId` و`assignment` إلزامية.

## 2. Cryptographic Failures

- كلمات المرور محفوظة كـ hash.
- الاتصالات في الإنتاج يجب أن تكون عبر HTTPS.
- الملفات الحساسة والنسخ الاحتياطية يجب أن تكون مشفرة.

## 3. Injection

- التحقق من المدخلات موجود عبر `zod` وORM.
- يجب تجنب أي بناء نصي مباشر للاستعلامات.
- يجب مراجعة أي HTML أو نص ديناميكي قبل عرضه.

## 4. Insecure Design

- يجب أن يبقى كل مسار حساس خلف صلاحية واضحة.
- يجب ألا تعتمد الواجهة وحدها على الإخفاء البصري.
- كل تغيير حساس يحتاج سجل تدقيق.

## 5. Security Misconfiguration

- إعدادات HTTPS وHSTS مفعلة في الإنتاج.
- يجب إبقاء `.env` خارج المستودع.
- يجب تعطيل أي تكامل خارجي غير معتمد.

## 6. Vulnerable Components

- يجب مراجعة الاعتماديات بانتظام.
- يجب تنفيذ `npm audit` ومراجعة النتائج قبل البيع.
- يجب تأجيل أي ترقية كبيرة إلى دفعة اختبار منفصلة.

## 7. Identification and Authentication Failures

- الجلسات محددة بمدة زمنية.
- تسجيل الدخول محدود بمسارات حساسة.
- يجب دعم MFA للمشرفين عند الحاجة.

## 8. Software and Data Integrity Failures

- يجب تسجيل عمليات التصدير والاستيراد والتفعيل.
- يجب أن تكون النسخ الاحتياطية قابلة للتحقق.
- يجب عدم قبول ملفات غير مفحوصة عند الرفع.

## 9. Logging and Monitoring Failures

- سجل التدقيق موجود.
- يجب الإبقاء على السجلات غير قابلة للتلاعب.
- يجب تسجيل المحاولات المرفوضة والمشتبه بها.

## 10. SSRF

- يجب عدم السماح بعنوان وجهة خارجي غير مقيد.
- أي تكامل خارجي يحتاج قائمة سماح واضحة.
- يجب مراجعة أي استدعاء شبكي جديد قبل الإطلاق.

## ملاحظات تنفيذية

- أضف فحص أمني لكل مسار حساس جديد.
- لا تضف تكاملات خارجية قبل تعريف الغرض منها في الوثائق.
- لا تعتمد على التخزين المحلي للبيانات الحساسة.
