## What SOM PRO is

SOM PRO is a hybrid school operations system with:

- a web frontend
- a backend API
- a separate license server
- a Windows desktop app
- shared logic and types in `packages/shared`

## Quick setup

1. Install dependencies:

```bash
npm install
```

2. Prepare the environment files listed in `README.md`.
3. Start PostgreSQL and Redis if you are using the local trial path.
4. Run database setup:

```bash
npm run setup:db
```

5. Start the app:

```bash
npm run dev
```

6. Start the license server when the local flow depends on it:

```bash
npm run dev:license-server
```

## Clean clone and delivery packages

- The repository baseline is source-first: a new engineer should be able to clone the repo, install dependencies, configure environment files from examples, run setup, and rebuild outputs locally.
- Commit application source, infrastructure configuration, mobile project files, mobile assets, scripts, and documentation that explain or reproduce the build.
- Do not commit real `.env` files, secrets, local database dumps, logs, `node_modules`, `dist/`, `deliverables/`, `reports/`, or generated installers.
- `dist/server/index.js` is a build output and must be regenerated by the documented build command instead of treated as source.
- `deliverables/` is produced by `scripts/runtime/build-delivery-packages.ps1`; rebuild it for each formal handoff after the source commit is verified.
